01 / The problem

The small jobs are where an agent goes quietly wrong.

An agent doing real work spends most of its time on unglamorous tasks: parse this document, profile this CSV, scan this repository for secrets, redact the personal data before it reaches a model. Each is small, and each is a place to be quietly wrong. A parser drops a column. A cleaner reports it lower-cased your strings and did not. The agent does not notice — it takes the output and builds on it, and by the time anything looks wrong the error is three steps upstream and invisible. There is no shortage of tools for these jobs. What is missing is any way for the caller to know the job was actually done.

04 / Difference

Knowledge that is justified, not merely asserted.

Three things this does that a similar-sounding service does not.

Every result states how far it was checked

The validation level sits in the response and inside the signed manifest, so a caller can require a minimum before acting on it.

Checks assert the work, not its shape

A check that only confirmed a key existed once let a no-op earn a signature. That class of bug is now structurally impossible.

Provenance is real

The replay capsule reports the interpreter and the installed library versions that actually ran, because that statement sits inside the signed manifest.

05 / How it works

The mechanism, in order.

What actually happens between your request and the signed answer.

  1. One envelope for all 48 — Every service returns the same shape: result, the named checks that ran, content-addressed input and output digests, a replay capsule, and an Ed25519 receipt. An agent writes one verification routine and it works for every tool.
  2. A level, not a rating — L1_PRODUCED produced a result. L2 validated it against the declared schema. L3_REPRODUCED re-ran the same input and got the same digest. L4_INDEPENDENTLY_VERIFIED ran a second independent engine and got an agreeing result.
  3. Checks assert the work — Not its shape. Ask for lower-case and the check fails unless every returned string really is lower-case. An unrecognised operation is a hard error, because signing “I did what you asked” is only defensible if unknown instructions fail loudly.
  4. Sign the manifest — Ed25519 over the canonical manifest, with the public key published at /.well-known/episteme-signing-key. Compare the key, verify the signature, and the receipt stands on its own.

How it is built

A Node gateway running OKX's official x402 seller SDK sits in front of a Python runtime. The gateway verifies and settles payment, then hands off over a constant-time internal secret — so a paid call is never challenged a second time, which is the failure that gets ASPs rejected. The runtime executes the node, runs its checks, attempts reproduction and differential verification, builds the replay capsule and signs the receipt. AI-backed services are flagged in their schema and capped below the deterministic tiers.

06 / Who pays

Why anyone buys this.

Agent builders who need a job done right and do not want to own the code. At $0.001–$0.20 a call, writing and maintaining your own parser is the expensive option. The receipt is what makes these worth buying rather than copying: in a pipeline where several agents hand work to each other, “prove the step you are passing me actually ran” is the missing primitive.

10 / Limits

What this does not do.

Printed here rather than buried.

  • Listed on OKX.AI as agent #9165 on 26 July 2026. Listed means OKX checked the service works; it says nothing about whether anyone wants it.
  • Zero sales. The marketplace is days old with near-zero volume across every ASP.
  • AI-backed services cannot reach the reproducible tiers, and are marked as such in their schema.
  • Produced artifacts are retained for a bounded period; the digest inside the receipt is the durable part.
